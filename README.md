## Ondo — 동대문 도매·소매 B2B 플랫폼

> AI-SW 마에스트로 17기 · 3인(백엔드 2 · 프론트엔드 1) · [저장소](https://github.com/minho-git/ondo-api)

동대문 도매상과 소매상은 **전화와 수기 장부로 주문을 주고받습니다.** 주문을 받고, 물건이
없으면 미송으로 남기고, 대금은 나중에 정산하는 과정이 수첩과 기억에 흩어져 있습니다.
주문이 어디까지 갔는지 물으려면 다시 전화를 걸어야 합니다.

온도는 그 과정을 시스템으로 옮깁니다. 도매가 상품을 한 번 등록하면 소매 마켓에 그대로
보이고, 소매가 넣은 주문은 도매 ERP로 바로 들어옵니다. 출고·미송·미수처럼 카카오톡으로
따로 알리던 내용도 소매처 화면에서 확인됩니다. 기획서를 먼저 쓰지 않고 도매 사장님들을
직접 만나 주문이 오가는 순서를 듣고, 그 순서를 그대로 API와 테이블로 옮겼습니다.

**서버 둘, DB 둘 구조입니다.** 소매 서버 전체와 도매의 정산·대시보드, AWS 인프라를 맡았습니다.

- **정산 원장** — 잔액을 고치는 대신 원장에 줄을 쌓고 거래처 행을 잠갔습니다.
  동시에 입금이 들어와도 잔액이 틀어지지 않고, 취소해도 기록이 남습니다.
- **대시보드 집계** — 매번 세던 것을 인덱스와 사전 집계, 개수 분리로 다시 설계했습니다.
  캐시는 재보고 나서 넣지 않기로 했습니다.
- **주문 접수 대기함** — 도매가 멈춰도 주문이 남도록 대기함을 주문서와 한 트랜잭션에 쓰고,
  워커가 SKIP LOCKED로 나눠 집어 재시도합니다. 지수 백오프와 지터로 몰림을 줄였습니다.
- **소매 서버** — 인증, 장바구니, 주문, 상품 목록, 미송, 정산 조회, 파일 업로드
- **인프라** — VPC, ECS Fargate, RDS, ALB, WAF를 Terraform으로 구성하고 GitHub Actions(OIDC)로 배포

앞의 셋은 고치기 전후를 같은 조건에서 재고 비교한 기록이 [저장소 README](https://github.com/minho-git/ondo-api#막혔던-곳과-푼-방법)에 있습니다.

`Java 21` `Spring Boot 4` `PostgreSQL 16` `Flyway` `JPA` `Testcontainers` `k6` `ECS Fargate` `RDS` `Terraform` `GitHub Actions`

## XFlow — 코드 없는 데이터 파이프라인 플랫폼

> 크래프톤 정글 11기 · 5인 · [저장소](https://github.com/minho-git/xflow) · [시연 영상](https://www.youtube.com/watch?v=WNXGnw_Wg8Q)

데이터를 한 곳에서 다른 곳으로 옮기려면 보통 **ETL 코드를 직접 짜고, 스케줄러에 등록하고,
실패하면 로그를 뒤져야 합니다.** 쓰는 사람이 데이터 분석가라면 그 과정 전체가 개발자에게
넘어갑니다.

XFlow는 그 과정을 웹 UI로 옮깁니다. 화면에서 소스와 변환을 고르면 Spark 잡으로 만들어지고
Airflow가 스케줄에 맞춰 돌립니다. 수집과 변환 쪽을 맡았습니다.

- **Kafka 스트리밍 수집** — API부터 Spark 잡까지 만들었습니다.
  정규식으로 비정형 로그를 컬럼으로 쪼개고, 오프셋에서 다시 시작하게 했습니다.
- **데이터 품질 검사** — 대용량 Parquet을 표본으로 검사하고 결과를 대시보드로 보여줍니다.
- **SQL 미리보기와 조인 키 탐지** — 동료와 같이 만들었습니다.
  샘플링으로 조인 키를 제안하고, 타입 캐스팅과 S3 pushdown을 붙였습니다.
- **ETL 에디터** — 소스 연결부터 변환 구성까지 화면을 만들었습니다.

`FastAPI` `Spark` `Kafka` `DuckDB` `S3` `React`
