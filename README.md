## Ondo — 동대문 도매·소매 B2B 플랫폼

> AI-SW 마에스트로 17기 · 3인(백엔드 2 · 프론트엔드 1) · [저장소](https://github.com/minho-git/ondo-api)

서버 둘, DB 둘 구조입니다. 소매 서버 전체와 도매의 정산·대시보드, AWS 인프라를 맡았습니다.

- **소매 서버** — 인증, 장바구니, 주문, 상품 목록, 미송, 정산 조회, 파일 업로드
- **도매 서버** — 정산 도메인(미수 원장·입금·배분·취소), 소매 접점 게이트웨이, 대시보드 집계
- **인프라** — VPC, ECS Fargate, RDS, ALB, WAF를 Terraform으로 구성하고 GitHub Actions(OIDC)로 배포

**정산 원장** — 잔액을 고치는 대신 원장에 줄을 쌓고 거래처 행을 잠가 순서를 세웠습니다.
같은 거래처에 동시 640건을 넣어 세 가지를 비교했습니다. 잠금을 빼면 잔액의 89%가 사라지고,
낙관적 락은 4,556번 재시도하고도 1건을 못 넣었습니다. 비관적 락은 정확하면서 38ms 느릴 뿐이었습니다.

**대시보드 집계** — 주문 300만 건에서 집계 6종 합계가 354ms였습니다.
인덱스 7종으로 전체 훑기를 없애고, 요약 표를 미리 채우고, 개수 세기를 분리해 0.2ms가 됐습니다.
쓰기 대가는 주문 건당 14%입니다. 캐시는 켜고 끈 차이가 0.5ms라 넣지 않았습니다.
부하를 걸다가 읽기 전용 트랜잭션 안의 DELETE와 커넥션 풀 자기 교착도 찾아 고쳤습니다.

**주문 접수 대기함** — 도매가 멈춰도 주문이 남도록 대기함을 주문서와 한 트랜잭션에 쓰고,
워커가 SKIP LOCKED로 나눠 집어 재시도합니다. 지수 백오프로 도매 호출을 85% 줄였고(9,193 → 1,401),
지터로 살아나는 순간의 몰림을 82% 더 줄였습니다(141 → 25).

`Java 21` `Spring Boot 4` `PostgreSQL 16` `Flyway` `JPA` `Testcontainers` `k6` `ECS Fargate` `RDS` `Terraform` `GitHub Actions`

## XFlow — 코드 없는 데이터 파이프라인 플랫폼

> 크래프톤 정글 11기 · 5인 · [저장소](https://github.com/minho-git/xflow) · [시연 영상](https://www.youtube.com/watch?v=WNXGnw_Wg8Q)

웹 UI로 ETL/ELT를 구성하면 Spark가 실행하고 Airflow가 오케스트레이션합니다.
수집과 변환 쪽을 맡았습니다.

- **Kafka 스트리밍 수집** — API부터 Spark 잡까지 만들었습니다.
  정규식으로 비정형 로그를 컬럼으로 쪼개고, 오프셋에서 다시 시작하게 했습니다.
- **데이터 품질 검사** — 대용량 Parquet을 표본으로 검사하고 결과를 대시보드로 보여줍니다.
- **SQL 미리보기와 조인 키 탐지** — 동료와 같이 만들었습니다.
  샘플링으로 조인 키를 제안하고, 타입 캐스팅과 S3 pushdown을 붙였습니다.
- **ETL 에디터** — 소스 연결부터 변환 구성까지 화면을 만들었습니다.

`FastAPI` `Spark` `Kafka` `DuckDB` `S3` `React`
